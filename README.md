# Inst room — магазин инструментов

React + TypeScript + Vite, структура FSD. Учебный проект по макету из Figma.

## Запуск

```bash
npm ci               # ставит ровно те версии, что записаны в package-lock.json
npm run dev          # http://localhost:5173
npm run build        # проверка типов + сборка
npm run lint
npm audit --omit=dev # уязвимости в том, что уходит пользователю
```

## Страницы

| Адрес                               | Страница                                                     |
| ----------------------------------- | ------------------------------------------------------------ |
| `/`                                 | главная                                                      |
| `/catalog`, `/catalog/:category`    | каталог (вкладки разделов и плитки подразделов)              |
| `/catalog/:category/:sub`           | товары подраздела: фильтры, сортировка, сетка/список         |
| `/collection/sale`, `/hits`, `/new` | акции, хиты сезона, новинки                                  |
| `/search?q=...`                     | поиск                                                        |
| `/brands`, `/brands/:slug`          | бренды                                                       |
| `/product/:id`                      | карточка товара (описание, характеристики, доставка, отзывы) |
| `/favorites`, `/compare`            | избранное, сравнение                                         |
| `/cart`, `/checkout`                | корзина, оформление в 3 шага                                 |
| `/account`                          | личный кабинет                                               |
| `/contacts`, `/news/:id`, `/about`  | контакты, новость, о компании                                |

Окна: заказ звонка, вход (телефон, потом код), регистрация, отзыв, «спасибо».

## Структура (FSD)

Импортировать можно только слои ниже текущего и только через `index.ts` слайса. Слайсы одного слоя друг друга не импортируют.

```
src/
├─ app/        провайдеры, роутер, layout, глобальные стили
├─ pages/      страницы (секции для одной страницы лежат в её ui/)
├─ widgets/    header, footer, products (карточка, слайдер, список с фильтрами)
├─ features/   cart, favorites, compare, auth, callback
├─ entities/   catalog (категории, бренды, товары, фильтры), news, shop
└─ shared/     ui, lib, config
```

## Картинки

Все пути описаны в одном файле: `src/shared/config/images.ts`. Файлы кладутся в `public/images`:

```
public/images/
├─ logo.svg                  логотип (уже есть, замените своим)
├─ common/    404.png, banner-1.png, banner-2.png
├─ home/      hero-1.png ... hero-4.png, about.png
├─ pages/     about-wide.png, about-side.png
├─ news/      1.png ... 4.png (карточки), cover.png, photo.png, bottom.png (внутри новости)
├─ products/  1.png ... 12.png   фото товаров
├─ categories/1.png ... 12.png   плитки каталога
└─ brands/    1.png ... 8.png    логотипы брендов
```

Номера идут по кругу: 888 товаров используют 12 фотографий. Нужно больше разных фото: поменяйте числа вверху `images.ts` (`PRODUCT_IMAGES` и другие) и добавьте файлы.

## Данные и демо-режим

- Товары генерируются (`entities/catalog/model/products.ts`), позже заменяются запросом к API.
- Вход: настоящей авторизации нет, подходит любой код из 4 цифр. История заказов в кабинете тестовая.
- Формы проверяют ввод, но никуда не отправляют данные.
- Корзина, избранное, сравнение и «вход» хранятся в localStorage и при чтении проверяются (`parseCart` и др.).

## Безопасность

1. Три рабочие зависимости (`react`, `react-dom`, `react-router-dom`), версии в `package.json` без `^`, точные в `package-lock.json`. Ставьте `npm ci`.
2. Результат `npm audit` меняется со временем: проверяйте перед каждой сдачей и деплоем. `npm audit --omit=dev` относится к тому, что уходит пользователю. Не запускайте `npm audit fix --force` не разобравшись: он может откатить пакеты.
3. Нет `dangerouslySetInnerHTML`, `eval`, `innerHTML`. Данные из адреса (поиск) и из localStorage выводятся как текст или проверяются.
4. Внешние ссылки с `target="_blank"` имеют `rel="noopener noreferrer"`.
5. `public/_headers` задаёт CSP и другие заголовки (Netlify и совместимые хостинги; для Vercel значения переносятся в `vercel.json`). В режиме разработки не действует.
6. Пароли и вход пока демонстрационные: когда появится бэкенд, всё проверять на сервере.
